# 03: 在試用交付中檢查資源衝突並提供人工暫停指引

**What to build:** 試用版本需要 script 或其他資源時，使用者從同一張試用工單的交付說明得知必要依賴、與開發的衝突，以及何時、如何暫停 Worker 後試用；Worker 不自行決定暫停。

**Blocked by:** 02: 由 Planner 插入普通 task，交付當下可跑的 bin。

**Status:** proposed — awaiting breakdown review

- [ ] Planner 的試用工單包含必要 script、設定及其他資源的檢查，Worker 回傳檢查範圍、證據、依賴位置與啟動條件。
- [ ] 可合理隨附的必要資源隨交付提供；仍需共用專案檔案、資料庫、裝置、連接埠或其他資源時，明確說明用途與衝突，不宣稱 bin 已完全獨立。
- [ ] 資源資訊不完整或無法完成可執行檢查時，明確標示尚未驗證的條件並交由 Planner 處理，不虛報可跑。
- [ ] 發現資源衝突時，由 Planner 根據 Worker 證據向使用者提示原因、建議暫停 Worker，以及適用於實際部署設定與位置的具體暫停指令。
- [ ] 提示明確說明 pause 只會阻止後續 task 派工，不會立即終止進行中的 task，並提供確認暫停狀態與安全開始試用的方式。
- [ ] 以實際 Worker 啟動設定與 launcher defaults 解析 pause，helper 指令帶入相同的自訂路徑／Worker ID；不讀取舊 worker env 檔，也不以預設路徑的狀態誤認自訂 Worker 已暫停。
- [ ] 試用 task 不因衝突而自行設置暫停旗標；使用者自行決定是否執行暫停指令，未暫停時 Worker 照常接續 queue。
- [ ] 在安裝後的示範專案驗證單一 bin、需要隨附 script、使用共用資源及自訂 pause 位置的情境；交付證據能說明各情境的啟動條件與暫停行為，不呼叫真實模型。
- [ ] 完整行為規格、來源覆蓋索引、操作與部署文件，以及相鄰實作規格的整合驗收，都一致描述本功能；舊 isolation／自動 preview 驗收已調整為專案目錄執行與按需求試用。
